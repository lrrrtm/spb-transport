# Архитектурные решения

Ключевые решения проекта, на которые ссылаются код и документация. Новое решение
добавляется в конец файла со следующим номером.

## ADR 0001: Границы хранилищ

Принято 20.09.2026.

Kafka — только буфер доставки с ограниченным retention. Вся долговременная история (raw,
silver, gold) лежит в HDFS в Parquet. Распределённые ETL, агрегации, признаки и модели
считаются только в Spark. Cassandra хранит готовые представления под конкретные запросы API,
а FastAPI не делает тяжёлых расчётов во время запроса.

Следствие: serving-слой можно целиком пересобрать из HDFS. Один и тот же результат может
лежать в нескольких таблицах Cassandra, только если к ним разные запросы. PostgreSQL,
Airflow и отдельное аналитическое хранилище не добавляем, пока для них нет задачи.

## ADR 0002: Формат realtime-событий

Принято 21.09.2026.

События в Kafka передаём в JSON и проверяем Pydantic-моделями, лишние поля запрещены. В
каждом событии есть `schema_version`. Несовместимое изменение — новая версия модели и новый
топик; совместимое добавление поля проходит через выборку и тесты совместимости.

Событий три вида: raw-ответ, позиция машины и снимок ETA. Сырой protobuf в raw-ответе
кодируется в base64, чтобы сохранить исходные байты.

Schema Registry пока не нужен. Вернёмся к нему, если станет много продюсеров и потребителей
или несовместимые изменения начнут дорого стоить.

## ADR 0003: Идентификаторы, время и дедупликация

Принято 23.09.2026.

Все временные метки хранятся в UTC с часовым поясом. Позиция идентифицируется SHA-256 от
`(vehicle_id, source_timestamp)`, снимок ETA — SHA-256 от машины, маршрута и упорядоченного
списка `(forecast_rank, stop_id, arrival_time)` без `collected_at`. У raw-запроса свой
`request_id`, повторы raw не удаляются. Часовой пояс `Europe/Moscow` используется только при
расчёте дня недели, временных интервалов и дня расписания.

Благодаря этому частый опрос API не плодит лишние позиции, а повторная запись в Cassandra
идемпотентна.

## ADR 0004: Сопоставление с маршрутом без trip_id

Принято 26.09.2026.

`route_id` из источника сужает набор shapes, но не определяет рейс и направление. Spark
выбирает shape и участок по близости к линии, направлению движения, последовательности
наблюдений и монотонности прогресса. У результата есть `confidence` и версия алгоритма,
машина может остаться несопоставленной.

Записи с низкой уверенностью сохраняем в silver, но не используем в метриках по участкам.
`trip_id` и `stop_sequence` не выводим и не придумываем. Пороги подбираем на реальной
выборке; новая версия алгоритма пишет новую версию производного набора, raw не трогаем.

Реализация (T09, октябрь 2026). Алгоритм `route-match-hmm-v1` — скрытая марковская модель по
треку машины: Viterbi выбирает путь, forward-backward даёт `confidence`, для выбросов есть
отдельное состояние `off_route`. Описание — в [`research/route-matching.md`](../research/route-matching.md).
Пороги подобраны на выборке 03.10.2026 (суббота, день) и задаются обязательными
переменными `ROUTE_MATCH_*`; что ещё нужно проверить на будних выборках — в
[`research/follow-ups.md`](../research/follow-ups.md). Результат пишется в silver
`vehicle_route_matches` ([контракт](../data-contracts/route-matches.md)) с полями
`match_status`, `confidence`, `run_id` и `algorithm_version`; метрики берут только `matched`.

## ADR 0005: Конфигурация и TLS

Принято 29.09.2026.

Каждое приложение читает настройки из переменных окружения в свою типизированную модель.
Без обязательной настройки приложение не запускается и пишет понятную ошибку. Общего
глобального конфига нет.

Проверка TLS включена по умолчанию. Выключить её можно только явным `GTFS_TLS_VERIFY=false`,
при этом при старте пишется предупреждение. Свой CA-бандл задаётся через `GTFS_CA_BUNDLE` и
передаётся в единый HTTP-клиент. `verify=False` в коде нет, предупреждения TLS глобально не
глушим. Пароли и ключи не имеют значений по умолчанию, `.env` не коммитится.

## ADR 0006: Сначала простые модели

Принято 02.10.2026.

ETA начинаем с исторических медиан по участкам. Аномалии сначала ищем понятными правилами.
Целевая переменная для замедления берётся из будущего прохождения участка, а не из
`arrival.delay`, которого нет. Для кластеризации используем интерпретируемые агрегированные
признаки.

Прибытие на остановку определяем по треку возле остановки с учётом направления, времени
стоянки и защиты от повторного срабатывания; пороги подбираем на выборке.

Более сложную модель добавляем, только когда накопится история и модель обгонит baseline на
отложенном по времени периоде. `/stopforecast` не используем, пока не изучим его данные.

## ADR 0007: Граница Spark–Cassandra serving

Принято.

Processed Parquet в HDFS нужен для воспроизводимой аналитики, но не подходит для
low-latency lookup текущего состояния транспорта и короткой истории одной машины.
Дублировать весь архив в Cassandra не требуется. Spark и Cassandra connector должны
использовать подтверждённо совместимые версии без скачивания JAR при старте job.

- Spark закреплён на 3.5.9 с Scala 2.12, Cassandra connector assembly — на 3.5.1.
- Kafka и Cassandra connector JAR добавляются в image при сборке с SHA-256 checksums.
- HDFS хранит канонические processed datasets; Cassandra хранит только query-oriented
  latest и bounded-by-day history tables.
- Schema применяется идемпотентным `cassandra-init` до старта streaming jobs.
- History writes идемпотентны за счёт детерминированных primary keys.
- Latest writes используют timestamp исходного наблюдения как Cassandra writetime. Replay
  старого события не может затереть более новое.
- Latest rows имеют обязательный TTL. Это ограничивает stale membership в таблице маршрута
  после смены `route_id`; consumers дополнительно фильтруют данные по freshness timestamp.
- Credentials необязательны только для локального no-auth режима и, если используются,
  задаются парой.

Spark 4 не используется, пока официальный connector не заявляет его поддержку. Добавление
новых Cassandra tables требует сначала определить endpoint/query pattern и оценить partition
size. Аналитические сканы и переобучение моделей читают HDFS, а не Cassandra.
