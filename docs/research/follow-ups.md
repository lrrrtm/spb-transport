Выборки A/B анализируются без Docker:

```shell
set -a; source <(grep -E '^(ROUTE_MATCH|STOP_EVENT)_' .env.example); set +a
uv run python scripts/research/analyze_route_matching_sample.py --with-matcher data/research/route-matching/<run>
uv run python scripts/research/analyze_stop_events_sample.py data/research/route-matching/<run>
uv run python scripts/research/analyze_matcher_edge_cases.py data/research/route-matching/<run> \
    --examples data/research/route-matching/<run>/edge-cases.csv
```

Отчёты сохраняются рядом с выборкой (`report.md`, `stop-events-report.md`, `edge-cases-report.md`); выводы переносятся в
`route-matching.md` / `stop-arrivals.md`, сами выборки в git не попадают.

## Прогон jobs на выгрузке HDFS (2026-10-03…05)

Выгрузка `/processed/vehicle_positions` Docker-пайплайна, static feed `e1271210…` (от 2026-10-03),
параметры `.env.example`, Spark `local[2]`, 2 ГБ driver, 2 ядра:

| Дата (часы UTC) | Позиций | Опросов в час | matched / low / off_route | Прогонов | Событий | interpolated / departure_only | stopped | Участков | route matching / stop events |
|---|---:|---:|---|---:|---:|---|---:|---:|---|
| 10-03 (15:00–16:51) | 412 195 | 95–109 | 87,4 / 3,1 / 9,4% | 14 416 | 39 383 | 12,3 / 6,3% | 58,5% | 26 901 | 808 с* / 61 с |
| 10-04 (16:36–18:32) | 603 003 | 342 (в 17 ч) | 88,9 / 2,8 / 8,4% | 7 282 | 48 955 | 6,9 / 3,7% | 68,7% | 43 039 | 473 с / 61 с |
| 10-05 (17:13–18:16) | 178 826 | ≈ 90 | 82,9 / 3,0 / 13,9% | 5 593 | 22 326 | 17,4 / 4,6% | 40,4% | 18 109 | 400 с / 56 с |

\* параллельно шёл другой анализ.

- Jobs отрабатывают на реальных данных без ошибок; на выходе 118 МБ `vehicle_route_matches`,
  26 МБ `stop_arrival_events`, 26 МБ `segment_traversals` за ≈ 5 часов наблюдений.
- **Скорость matching.** Время мало зависит от объёма: 400 с на 179 тыс. позиций, 473 с на
  603 тыс. По разнице переменная часть — около 6 тыс. позиций/с, остальное (≈ 6 минут) —
  постоянные затраты job; причина не проверялась (кандидаты — `groupByKey` на 200 партиций и
  построение индекса shape в каждом Python-воркере). При нормальном опросе источник даёт
  ≈ 0,7 млн уникальных позиций в час, то есть сутки — 12–14 млн позиций и порядка 40 минут на
  `local[2]`. Для ПК с ограниченной памятью это приемлемо, если запускать jobs при остановленных
  стримах.
- **C.1 Частота опроса.** Коллектор в Docker должен опрашивать `/vehicle` раз в 10 с (360 раз в час),
  а сделал 95–109 опросов в час 3 октября и ≈ 90 — 5 октября; нормальная частота была только
  4 октября в 17 ч UTC. При редком опросе вдвое-втрое больше прогонов на позицию и
  `interpolated`-событий, меньше `stopped` и `matched`. Лёгкий скрипт выборок на том же ПК опрашивает
  без пропусков (540 из 540). Вероятная причина — нехватка памяти и CPU на ПК под всем стеком;
  проверить по логам `collector` (длительность цикла, ошибки) при следующем запуске Docker.
  Для исследований пользоваться скриптом выборок, Docker — для проверки пайплайна.
- 5 октября 309 позиций без shape и больше `off_route`: использовался feed от 3 октября, а
  маршрутная сеть к 5-му обновилась. В Docker `spark-static-gtfs` нужно запускать перед batch-jobs
  каждого дня.
